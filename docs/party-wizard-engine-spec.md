# موتور «جشن منو بساز» — طراحی کامل سیستم (نسخه ۱)

> این سند شامل معماری، جریان داده، و **فایل‌های پیکربندی قابل‌ویرایش بدون کدنویسی** برای موتور پیشنهاد ویوراست.

---

## ۱. معماری کلی (۵ مرحله)

۱. مشتری متن آزاد تایپ می‌کند («جشن تولد ۷ سالگی دخترم، ۲۰ مهمون، بودجه ۸ میلیون، تم باربی»)
۲. یک تماس API سبک و ارزان (نه مدل لوکال، چون فرکانس پایینه) متن رو به فیلدهای ساختاریافته تبدیل می‌کنه: `{ ageGroup, gender, guestCount, budget, theme, city, venue }`
۳. مشتری فیلدهای استخراج‌شده رو به‌صورت کارت‌های قابل‌ویرایش می‌بینه و تایید/اصلاح می‌کنه
۴. **موتور قانون‌محور** (بدون AI — کد قطعی و قابل‌پیش‌بینی) روی این داده‌ی تمیز اجرا می‌شه:
   - نگاه به جدول «تخصیص بودجه» بر اساس نوع جشن
   - فیلتر محصولات/خدمات موجود در همون شهر، هماهنگ با تم، داخل بازه‌ی قیمتی هر دسته
   - انتخاب بهترین گزینه‌ی هر دسته (بر اساس امتیاز، تطبیق تم، موجودی)
۵. توضیح نهایی از روی **قالب متنی از پیش نوشته‌شده** پر می‌شه (نه تولید AI) و لیست محصول قابل خرید نمایش داده می‌شه

**نکته‌ی کلیدی برای تو:** فایل‌های بخش ۳ و ۴ این سند (تم‌ها، تخصیص بودجه، قالب متن) رو با Claude Code به‌صورت فایل‌های ساده‌ی JSON/YAML پیاده می‌کنیم — یعنی هروقت خواستی چیزی عوض کنی، فقط یه فایل متنی رو ویرایش می‌کنی، نیازی به دست‌زدن به کد اصلی نیست.

## ۳. جدول تخصیص بودجه (نمونه‌ی اولیه — قابل‌تنظیم)

این نسبت‌ها فقط یه **نقطه‌ی شروع منطقی** هستن؛ بعد از چند سفارش واقعی باید با داده‌ی واقعی اصلاح بشن.

| دسته | درصد پیش‌فرض بودجه | یادداشت |
|---|---|---|
| بادکنک‌آرایی و دکور | ۳۰٪ | معمولاً بیشترین سهم بصری جشن |
| ظروف و لوازم یک‌بارمصرف هماهنگ با تم | ۱۵٪ | بشقاب، لیوان، کارد و چنگال، سفره |
| کیک و شیرینی | ۲۰٪ | شامل تاپر و شمع |
| گیفت/هدیه‌ی مهمانان | ۱۰٪ | متناسب با تعداد مهمان |
| لباس/اکسسوری (کلاه، نقاب) | ۵٪ | اختیاری بسته به تم |
| خدمات جانبی (عکاس، دی‌جی و…) | ۲۰٪ | فقط اگر بودجه اجازه بده و در آن شهر/فاز فعال باشد |

**قانون سرریز:** اگر بودجه‌ی کل خیلی کم باشه (مثلاً زیر ۳ میلیون تومان)، خدمات جانبی خودکار حذف می‌شه و بودجه‌اش بین بادکنک‌آرایی و ظروف تقسیم می‌شه.

## ۴. نمونه‌ی قالب توضیح متنی (بدون AI، فقط پرکردن جای خالی)

```
برای جشن {party_type} با تم {theme}، مناسب سن {age_group} و {guest_count} مهمان،
این ترکیب رو با بودجه‌ی {budget} تومان براتون آماده کردیم.
بیشترین سهم بودجه برای {top_category} در نظر گرفته شده چون معمولاً
بیشترین تاثیر رو روی حس‌وحال جشن می‌ذاره.
```

می‌تونی هر وقت خواستی این متن رو (و نسخه‌های مختلفش برای تم‌های مختلف) عوض کنی — فقط یه فایل متنیه.

---

## ۵. داده‌هایی که در PartyProfile هر بار ذخیره می‌شن (فلایویل داده)

- متن خام تایپ‌شده‌ی مشتری
- فیلدهای استخراج‌شده توسط AI + آیا مشتری چیزی رو اصلاح کرد یا نه (سیگنال کیفیت استخراج)
- بودجه‌ی واقعی وارد شده
- پیشنهاد نهایی‌ای که سیستم داد
- سبد نهایی‌ای که مشتری واقعاً خرید (چقدر با پیشنهاد اولیه فرق داشت؟)
- **تاریخ تولد مشتری** (یک‌بار در پروفایل حساب کاربری ثبت می‌شه، نه هر بار) — برای پیامک تبریک/تخفیف نزدیک تولد در آینده

---

## ۶. اتصال هوش مصنوعی — فقط API و لینک، بقیه خودکار

هدف: تو فقط باید یک آدرس API و یک کلید بدی؛ هیچ کد یا منطقی دستی لازم نباشه.

**طراحی:**
- یک بخش «تنظیمات هوش مصنوعی» در پنل ادمین با ۳ فیلد ساده: آدرس API، کلید API، نام مدل (اختیاری).
- کل پروژه از یک لایه‌ی انتزاعی به اسم `AIExtractorProvider` استفاده می‌کنه — یعنی در کد فقط یک نقطه‌ی اتصال وجود داره، نه پخش‌شده در چند جا.
- این لایه از استاندارد رایج API مدل‌های زبانی (فرمت سازگار با OpenAI/Anthropic API) پیروی می‌کنه، پس تقریباً با هر سرویس هوش مصنوعی که بعداً انتخاب کنی (چه ایرانی چه خارجی) کار می‌کنه، فقط با تغییر همون ۳ فیلد در پنل ادمین.
- اگر این تنظیمات خالی باشه، سیستم خودکار به همون فرم چندمرحله‌ای قبلی (انتخاب از گزینه‌ها) سوییچ می‌کنه — یعنی جشن‌ساز هیچ‌وقت از کار نمی‌افته، فقط از حالت تایپ‌آزاد به حالت انتخابی برمی‌گرده.

## ۷. داشبورد بررسی داده‌های جشن‌ساز (برای خودت)

یک بخش جدید در پنل ادمین («داده‌های جشن‌ساز») که بهت اجازه می‌ده رفتار واقعی کاربران رو ببینی:

- **جدول کامل PartyProfile:** هر ردیف = یک بار استفاده از جشن‌ساز، با متن خام، فیلدهای استخراج‌شده، آیا مشتری اصلاح کرد، پیشنهاد نهایی، آیا خرید انجام شد یا نه.
- **آمار خلاصه:** پرتکرارترین تم‌ها، میانگین بودجه‌ی هر نوع جشن، نرخ تبدیل «پیشنهاد دیدن» به «خرید کردن»، نرخ خطای استخراج AI (چند درصد مواقع مشتری مجبور شد فیلدها رو دستی اصلاح کنه — این سیگنال مهمیه که آیا AI انتخابی خوب کار می‌کنه یا نه).
- **فیلتر بر اساس بازه‌ی تاریخ، شهر، نوع جشن** برای بررسی روند.
- این دقیقاً همون چیزیه که بعداً برای تنظیم دستی جدول تخصیص بودجه (بخش ۳) و تصمیم‌گیری درباره‌ی فاز بعدی لازم داری.

## ۸. نظرات و امتیاز مشتری — محل قرارگیری

بررسی کردم؛ وایرفریم مرجعی که فرستادی یه صفحه‌ی اختصاصی برای امتیازدهی نداره (یه wireframe kit عمومیه، همه‌چیز رو پوشش نمی‌ده). پیشنهاد استاندارد و منطقی:
- **صفحه‌ی جزئیات محصول/خدمت:** لیست نظرات + میانگین امتیاز، زیر توضیحات محصول
- **صفحه‌ی تاریخچه‌ی سفارش (بعد از تحویل):** یک پیام «این سفارش رو چطور ارزیابی می‌کنید؟» با ستاره، دقیقاً روی همون الگوی لیست سفارش‌ها که در وایرفریم دیدیم (صفحات لیست با آیکون قلب/علاقه‌مندی) — همون‌جا یه دکمه‌ی ستاره اضافه می‌کنیم.
