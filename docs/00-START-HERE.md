# شروع کن اینجا — راهنمای Claude Code برای ساخت پروژه‌ی Viora

> این فایل نقطه‌ی ورود پروژه‌ست. اول این رو کامل بخون، بعد بقیه‌ی فایل‌های این پکیج رو به ترتیب زیر بخون، بعد شروع به ساخت کن.

---

## ۰. یک قانون مهم قبل از هرچیز: مستندسازی برای آینده

این پروژه قراره سال‌ها زنده بمونه و ممکنه ۲ سال دیگه یک هوش مصنوعی یا توسعه‌دهنده‌ی دیگه (نه لزوماً Claude) بخواد روش کار کنه، بدون این‌که به این مکالمه دسترسی داشته باشه. پس:

1. **همه‌ی فایل‌های این پکیج رو عیناً در مسیر `/docs` داخل ریپازیتوری پروژه کپی کن** (نه فقط بخون و دور بنداز). این‌ها مرجع دائمی پروژه‌ان، نه یک بریف یک‌بارمصرف.
2. هر تصمیم معماری مهم که خودت (Claude Code) در حین ساخت می‌گیری رو در فایل `/docs/decisions.md` با فرمت کوتاه ثبت کن: چه تصمیمی، چرا، چه گزینه‌های دیگه‌ای رد شد. این کار «Architecture Decision Record» نام داره و باعث می‌شه هر AI/توسعه‌دهنده‌ی بعدی بفهمه *چرا* کد این‌شکلیه، نه فقط *چیه*.
3. کد رو ساده و استاندارد بنویس (Next.js/Prisma به روش متعارف خودشون)، نه ترفندهای هوشمندانه‌ی غیرمعمول — خوانایی برای آینده مهم‌تر از زیرکی امروزه.
4. یک فایل `/docs/README.md` بساز که فهرست کل مستندات، ساختار پوشه‌ها، و «از کجا شروع کنم» رو برای هر خواننده‌ی جدید (انسان یا AI) توضیح بده.
5. هر جا پیکربندی (تم‌ها، بودجه، تنظیمات AI) رو در فایل جدا (نه هاردکد در کد) گذاشتی، در `/docs/README.md` بگو کجاست و چطور ویرایش می‌شه.

## ۱. ترتیب مطالعه‌ی فایل‌های این پکیج

1. `project-plan-v1.md` — چشم‌انداز، مدل کسب‌وکار، نقشه‌راه فازبندی‌شده، معماری کلی
2. `party-wizard-engine-spec.md` — طراحی کامل موتور جشن‌ساز (شامل اتصال AI پلاگین‌پذیر و داشبورد داده)
3. `panels-and-operations-spec.md` — مسیر سفارش تک/چندفروشنده، پنل فروشنده، پنل پارتنر تولید (چاپ بادکنک)، پنل ادمین کامل
4. `sprint-0-brief.md` — اسکوپ دقیق اولین اسپرینت (این رو با تغییرات بخش ۲ همین فایل اجرا کن)
5. `legal-pages-draft.md` — پیش‌نویس صفحات قانونی (برای صفحات Terms/Privacy/Refund)
6. `wireframes/` (پوشه‌ی تصاویر) — مرجع ساختار UI. اگر این پوشه در پکیج نبود، از کاربر بخواه مستقیم آپلودشون کنه.

## ۲. به‌روزرسانی‌های مهم نسبت به Sprint 0 اولیه

این‌ها بعد از نوشتن `sprint-0-brief.md` تصمیم‌گیری شدن و باید لحاظ بشن:

- **نام پروژه/برند:** Viora (از ترکیب Vivid + Aura). دامنه‌ی نهایی هنوز مشخص نیست — از کدنیم `viora` در کل پروژه (نام ریپازیتوری، دیتابیس، متغیرها) استفاده کن؛ دامنه بعداً بدون تغییر کد وصل می‌شه.
- **هاست هدف:** cPanel با قابلیت Node.js Selector (نه Vercel/Liara). پس تنظیمات build باید با این نوع هاست سازگار باشه (بدون وابستگی به فیچرهای مخصوص Vercel).
- **اتصال هوش مصنوعی جشن‌ساز:** طبق بخش ۶ فایل `party-wizard-engine-spec.md` — یک لایه‌ی انتزاعی `AIExtractorProvider` بساز که فقط با سه فیلد (API URL, API Key, Model Name) از پنل ادمین پیکربندی بشه. تا وقتی این فیلدها خالی‌ان، جشن‌ساز باید با فرم چندمرحله‌ای معمولی (بدون AI) کار کنه، نه این‌که خراب بشه.
- **داشبورد داده‌ی جشن‌ساز:** طبق بخش ۷ همون فایل، یک صفحه در پنل ادمین برای دیدن و فیلتر کردن داده‌های PartyProfile اضافه کن.
- **مسیر سفارش تک‌فروشنده/چندفروشنده:** سفارش تک‌فروشنده مستقیم توسط فروشنده ارسال می‌شه؛ سفارش چندفروشنده (خروجی جشن‌ساز) باید state machine جدا داشته باشه: در انتظار ارسال به مرکز → دریافت‌شده در مرکز → کنترل کیفیت → ارسال نهایی. فعلاً هزینه‌ی اضافه از مشتری گرفته نمی‌شه.
- **پنل فروشنده‌ی محصول، پنل پارتنر چاپ بادکنک، و پنل ادمین:** مشخصات کامل هر سه در `panels-and-operations-spec.md` آماده‌ست.
- **حریم داده‌ی حساس:** تاریخ تولد مشتری (اختیاری) در پروفایل کاربر ذخیره بشه، برای مصارف بازاریابی آینده (پیامک تبریک/تخفیف) — نه برای الان.
- **پیامک:** فعلاً کاملاً mock (console.log کافیه)؛ در پشت یک `SMSProvider` انتزاعی که بعداً به یک سرویس واقعی ایرانی وصل می‌شه.
- **پشتیبانی:** تیکت داخل پلتفرم برای مشتری (نه ایمیل خارجی)؛ برای پارتنرهای چاپ/فروشنده، فقط یک بلوک اطلاعات تماس با تیم ویورا (شماره/ایمیل/تلگرام، قابل‌ویرایش از تنظیمات ادمین) نمایش داده بشه، نیازی به سیستم تیکت جدا برای اونا نیست.

## ۳. وضعیت wireframe ها

تصاویر پوشه‌ی `wireframes/` مرجع ساختار و چیدمان صفحات موبایل هستن (بدون رنگ نهایی — پوسته‌ی رنگی طبق «Champagne Rose» در `project-plan-v1.md` پیاده می‌شه). این تصاویر بدون شماره‌گذاری معنادار هستن (000 تا 212)؛ اگر معنای دقیق یک صفحه‌ی خاص نامشخص بود، از کاربر بپرس به‌جای حدس زدن.
